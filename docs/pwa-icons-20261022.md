# Approved PWA identity repair — 2026-10-22

Production baseline: ebbea3473f260f73ba426021ba0c40c5de31ea6d, confirmed through the existing taallamt-teacher Vercel project and its taallamt-teacher.vercel.app alias. The separate newer student Preview remains on its own existing branch; none of its unmerged learning/auth/link work is promoted by this Production patch.

Root cause: the in-page startup image had been updated on Preview, but the installed app identity still referenced independent old teacher/student PWA artwork. The deployed Production baseline did not expose the newer manifest/icon metadata. Android can display its installed icon before any website JavaScript runs; changing only the web splash therefore cannot fix that first screen.

The supplied PNG is preserved without regenerating the character. The versioned source has genuine RGBA transparency. Both role manifests and the authenticated per-student manifest use versioned 192/512 any icons plus a 512 maskable icon. Any icons are transparent. Maskable and Apple icons have an intentional opaque #e0f4ff background with protected margins; all non-background pixels stay inside the maskable safe circle. Names, routes, scope and existing student invitation start URLs are preserved. Versioned ICO favicon and Apple icons use the same image. Old icon filenames are retained as compatibility aliases containing the new artwork.

pwa-identity.js centralizes the role-specific manifest, touch icon, favicon, theme and Service Worker registration. Both existing HTML entry points use the exact source on a light-blue startup background. The dynamic manifest reuses existing authorization and does not write student records. No authentication, credential, Firebase configuration, roster, learning logic or student data has been changed.

The Service Worker uses the network with no-store for installation artwork/metadata, requests immediate activation, and deletes only old cached identity resources from this site's named caches. Cached student work and all browser storage remain untouched. Manifest/worker/icon response headers revalidate stale browser copies.

Both full builds and TypeScript passed. Added API checks verify own-student authorization, unchanged start URL identity/token, missing/wrong-token rejection and zero writes during manifest generation. Service Worker VM checks verify stale icon eviction, retention of cached answers and identity-only no-store behavior. Image checks verify dimensions, source equality/alpha, transparent any icons, fully opaque blue maskable/Apple backgrounds, and maskable safe bounds.

Live Preview and Production runtime results are recorded in the associated pull request after deployment, rather than inferred from Build success. Physical Android Chrome installation, launcher icon refresh and native WebAPK splash cannot be exercised from the cloud browser and are not claimed as tested.

Existing installed icons cannot be forcibly replaced by website code. Chrome 144+ may offer Review app update for identity changes; the user can accept it. Old simple launcher shortcuts or devices retaining old metadata may require removing and re-adding the shortcut from the exact existing link, preserving site data. No link/token replacement is required. Primary reference: https://developer.chrome.com/blog/improvements-to-web-app-updates (2026-01-21).
