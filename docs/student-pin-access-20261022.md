# Permanent student entry and numeric PINs

The existing Vercel project `taallamt-teacher` and existing Production data workspace are retained. `shakabambo.vercel.app` is an additional verified Production domain; old domains, invitation links and student identifiers are retained. Root and `/student-login` present the approved trophy artwork, student names from the existing roster, and a six-digit numeric code. `/teacher` keeps its existing protected teacher gate.

PIN verification uses server-side salted scrypt; plaintext PINs are returned once to the authenticated teacher when issued, and are never stored. Teacher issuance/reset/revocation requires same-origin authorization plus a completed workspace backup. The teacher can copy a new code or download only the codes issued within the current page session. Reloading deliberately removes plaintext delivery codes; existing codes can be reset, never recovered from hashes. Login attempts are limited transactionally by both client address and student identifier.

Student sessions are opaque 256-bit random tokens. Only their SHA-256 digests are stored in Firestore. Cookies are Secure, HttpOnly, SameSite=Lax, host-only, Path=/api and last 180 days. Records are scoped to the data workspace and credential revision, not a deployment, app build, hostname string, or teacher password. Reset/revoke invalidates previous PIN sessions but does not change the existing guardian invitation. Old-domain cookies remain on that domain; new-domain entry needs its own first login. Logout revokes the current session. Authorized teacher previews remain available.

Backups copy the existing workspace root and every nested collection/document, including Firestore value types, into `studentLoginBackups/{workspace}/snapshots/{backupId}/documents/{sha256-original-path}`. Every row carries its original path and data. Reads are paginated; the traversal queue and count are checkpointed atomically with each copied batch. Credential mutations remain blocked until the manifest is marked complete. A backup older than 24 hours cannot authorize a mutation. The pre-change credential is also retained in an audit document. This does not replace a managed database point-in-time backup or copy the actual contents of Cloud Storage attachments; existing attachment references are retained. Recovery consists of reviewing the complete manifest, checking row count/path mapping, then using the existing Firebase Admin operator process to restore the recorded data at its original paths. No live recovery or deletion is performed by this change.

Validation: full project build, 29 Vitest tests, 39 existing API journeys and dedicated student PIN regressions. Tests cover correct/wrong numeric codes, Arabic numeral normalization, unauthorized management, CSRF, cookie tampering, expiry, reset/logout revocation, cross-student denial, teacher previews, authenticated message reads, backup data fidelity, existing invitation compatibility and unchanged educational fixture records. Public login UI and original PNG transparency were inspected. Live Staging created a complete backup of 1552 workspace documents before issuing a test PIN; correct PIN returned 200, wrong PIN 401, own student home 200, another student denied. Live sequential-deployment verification and Production smoke results are recorded in the PR after execution.

Physical Android launcher/WebAPK installation, native splash and complete browser process restart are not tested in the remote browser. Existing installed shortcuts may require accepting an icon update or re-adding the same link. The existing role manifests and approved transparent PNG/light-blue maskable assets remain in use. No dependency was added. The deployed baseline has no package lockfile, so native npm audit cannot run against a committed lockfile; no audit pass is claimed.
